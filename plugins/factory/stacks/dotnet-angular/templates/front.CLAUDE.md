## Structure

```
apps/{{app}}/src/app/
  {feature}/
    data-access/      repositories over @{{client_scope}}/api, the feature store (*.store.ts)
    pages/            routed pages (*.page.ts), the feature routes file
    ui/               dumb components (inputs/outputs only), forms (*.form.ts)
libs/api/             the generated client: never edited by hand, regenerated by `prepare`
libs/{shared libs}/   shared UI, utils, i18n
```

## Conventions

- Standalone components, `OnPush`, signals for state, `inject()` over constructor injection, `@if` / `@for` control flow.
- **Data:** a page talks to its store; the store talks to a repository; the repository is the only place that calls the generated client. State is signals (`resource` / `linkedSignal` where it fits); every mutation reloads or patches the state explicitly.
- **Pages** are routed, thin, and compose UI components; **UI** components are dumb: inputs, outputs, no injection of stores or services.
- **Forms:** one `*.form.ts` per form holding the model, validators and the error mapping from the API's problem details.
- **i18n:** every user-facing string goes through the translation layer; keys live in `{{i18n_file}}`, named `{feature}.{element}.{text}`; a missing key is a review finding.
- **Styling:** {{styling}} (component styles scoped; no global overrides outside the theme).
- File naming: `{name}.page.ts`, `{name}.store.ts`, `{name}.form.ts`, `{name}.component.ts`, `{name}.repository.ts`.
