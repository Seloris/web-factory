# Review

Read `${CLAUDE_PLUGIN_ROOT}/reference/workflow-rules.md` first (the project, manifest, subagents, language, commits). The prompt gives the scope: `/selo-flow:review` (the uncommitted changes and the last commits of this work), `/selo-flow:review {range or files}`, `/selo-flow:review {plan folder}` (the plan's implementation: from the commit that added its `plan.md` to `HEAD`, plus the uncommitted changes) `/selo-flow:review plan {plan folder}` (the plan itself, before it is implemented) or `/selo-flow:review {slug}` (a whole area: its `00_spec.md` against the code, every FR and BR checked, on request).

1. Spawn the `reviewer` agent with the Agent tool, `model:` the manifest's `models.reviewer`, and a caveman-voice task naming the scope: the uncommitted changes plus the commits the person names by default (ask which when it is not clear: the base branch holds every session's work); the range, files or plan folder the person gave; `plan {plan folder}` for a plan review; for an area, the spec file and the instruction to check each FR and BR against the code (built, missing, or behaving otherwise) and each `(planned)` FR still unbuilt. Add the plan folder or the agreed approach when you know it.
2. Wait for its report. Never edit code in this skill: the only file it touches is the plan's Validation (step 4).
3. Relay the findings to the person in `language.chat`, rewritten in normal prose, in the reviewer's order and with its tags and `file:line`, then its verdict line.
4. **Record the review** when the scope was a plan's implementation (`/selo-flow:review {plan folder}`) and no finding is left, fixed or left open with the person's agreement: tick `Review` in the plan's Validation and propose its commit, `chore({slug}): validation — Review`, the message in a code block, on the person's yes. A review with findings leaves `Review` as it is: the fixes' commit ticks it.
5. End with the next prompts (for an area: `/selo-flow:write-spec {slug}: {the gaps to record}` or `/selo-flow:implement {a gap to fix}`): `/selo-flow:implement fix findings {numbers} of the review` for code, `/selo-flow:write-plan revise {plan folder}: findings {numbers}` for a plan, and `/selo-flow:review {plan folder}` again after the fixes while the plan's `Review` is still `[ ]`; none once it is ticked. The findings live only in this session: the fix prompt is run here, or its session gets the findings pasted in.
