Factory v2

A smooth workflow that drives an application with up-to-date specs: two speeds (fastlane dev, specified feature), a spec the code keeps up to date and that you see move every evening, parallel sessions that commit on develop without getting in each other's way. Plate 1

Two lanes, one mechanism

The autopilot picks the lane on a free request; — with plan forces the feature lane. implement {request} is always the fastlane. Both lanes end the same way: review, demo, commit on develop.

/factory:autopilot {request | slug | plan}
▼ the planner judges the size
a single component · no new business rule or entity?

Fastlane yes · ~10 min

  1. Name the spec area touched
  2. Code + tests, build / test / lint
  3. Spec delta in the same commit
  4. Review on the diff (reviewer)
  5. Test on the demo if UI
  6. Commit on develop, by named files

Feature lane no · 30–60 min

  1. Spec, multiple-choice grill (2 rounds) if interactive
  2. Plan: Business decisions ≤ 5, then Technical defaults
  3. Stages, one commit each
  4. Review of the whole plan, once, at the end
  5. Full suites, test on the demo
  6. Report: Business decisions first

Plate 2

Five sessions, zero collisions

Two phases. Step A, right away: everyone commits on develop, each their own files, no more branches or squash. Step B, after a trial: each session that writes has its worktree and lands by fast-forward when everything is green; your servers reload the landed code.

Step A · shared develop

  • git commit -- {my files}, never add -A or --amend
  • a file modified by another session: stop, say so
  • dirty tree: no longer a blocker
  • red suite outside my diff: replayed on HEAD, “not ours”

Step B · one worktree per job

The rest of this plate. Also settles the suite that runs on another session's half-done work. Cost to measure first: node_modules and ignored files per worktree.

What land does

  1. lock: two landings never cross
  2. checks: clean worktree, review ticked, green suites
  3. git rebase develop; conflict = stop
  4. duplicate spec ids renumbered
  5. re-test if the pulled-in commits touch my components
  6. git -C <main> merge --ff-only
  7. worktree removed; “npm install needed” flagged

What goes away

The squash and its 10 lines of git, — close the branch, commits amended to remove another session's files, the autopilot blocked on “tree not clean”, the branch-name question.
