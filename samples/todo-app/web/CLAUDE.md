# web — the todo-app front: the home page lists, creates and deletes tasks

```component
kind: front
stack: react-express
layers: [data, pages, ui]
commands:
  build: npm run build
  lint: npx eslint {files}
  prepare: npx openapi-typescript ../api/openapi.json --output src/api/schema.d.ts
```

All commands run from this component's path. The front has no unit tests: never create a `*.test.tsx`. Lint only the files a stage changed, never the whole app.

## Structure

```
src/
  main.tsx                  React root, QueryClientProvider, RouterProvider
  router.tsx                the route tree, one lazy route per feature page
  api/
    schema.d.ts             generated by `prepare` from the API's OpenAPI document: never edited by hand
    client.ts               the openapi-fetch client (`createClient<paths>`), base URL, problem-details handling
  features/{feature}/
    data/                   query and mutation hooks over the client (`use{Entity}Query`, `use{Action}Mutation`), query keys
    pages/                  routed pages (`{Name}Page.tsx`)
    ui/                     presentational components (props in, callbacks out), forms (`{Name}Form.tsx`)
  shared/
    ui/                     shared components
    lib/                    utils, i18n
```

## Package scripts

| Script | Does |
|---|---|
| `build` | `tsc -b && vite build`: type-checks, then bundles |
| `dev` | `vite`, with the `/api` proxy to http://localhost:3000 |

## Conventions

- **TypeScript strict**, function components, hooks; no default exports except where React Router's lazy routes need them; no `any`.
- **Data:** a page uses its feature's `data/` hooks; the hooks are the only place that calls the API client; the client is the only place that calls `fetch`. Server state lives in TanStack Query (one query-key factory per feature, every mutation invalidates or updates the queries it changes); local UI state in `useState`/`useReducer`; no global store unless several features share client state.
- **Types** of requests and responses come from `src/api/schema.d.ts` (`paths`, `components["schemas"][...]`), never redeclared by hand.
- **Pages** are routed, thin, and compose UI components; **UI** components receive props and emit callbacks: no data hook, no client call inside them.
- **Forms:** one `{Name}Form.tsx` per form, holding its fields, validation and the mapping of the API's problem details (`400` field errors) to field messages.
- **i18n:** every user-facing string goes through the translation layer; keys live in `src/shared/lib/i18n.ts`, named `{feature}.{element}.{text}`; a missing key is a review finding. The application's UI language is French.
- **Styling:** CSS Modules (styles scoped to their component; no global overrides outside the theme).
- **Loading and errors:** every page that reads data shows a loading state and an error state; a failed mutation shows the problem details' message.
- **No sign-in:** the application has no accounts; the client sends no auth header and no page is guarded.
- File naming: `PascalCase.tsx` for components and pages, `camelCase.ts` for hooks and utils (`useTasksQuery.ts`).

## Testing

None on the front. The `test-in-browser` skill checks a change in the real app on http://localhost:5173; there are no test accounts, nothing to sign in with.

## Local run

- Prerequisites: Node 22, `npm ci`.
- Run: `npm run dev` → http://localhost:5173; the API must be running on http://localhost:3000.
- `prepare` regenerates `src/api/schema.d.ts` from the API's committed handoff file; run it at the start of every front stage.
